# Future work: move off the interim GitHub CDN onto Firebase

**Status as of 2026-07-09:** real audio content (1340 files, 10 languages,
generated by `tools/build_catalog.py`) is live on a free interim CDN at
`https://raw.githubusercontent.com/prince11jose/globalradio-cdn-content/main`
(see that repo's README). The app's Firebase project is `globalir` (adopted
as the production project on 2026-07-09 — see CHANGELOG.md — after
`globalradio-1f547`, the originally intended project, turned out to have no
IAM access available to the account doing this work, and no OAuth client
fingerprint registered, which was breaking Google Sign-In).

The one remaining real blocker on `globalir` is billing:

- **Cloud Storage requires an active billing account to create a bucket at
  all** — unlike Firestore, there is no free-tier bucket creation. Confirmed
  directly: `gcloud beta billing projects describe globalir` →
  `billingEnabled: False`, and a direct Storage API bucket-create call
  returned `"The billing account for the owning project is disabled in
  state absent"`.

None of this needs a redesign — the code and scripts for the real setup
already exist and are tested against `globalir`, minus the Storage billing
wall. **When billing is enabled on `globalir`, run this checklist top to
bottom.** Each step is idempotent/safe to re-run.

## Prerequisites (one-time, human, no way around this)

- [ ] Billing account linked to `globalir`: https://console.cloud.google.com/billing/linkedaccount?project=globalir

## 1. Firestore database + rules (if not already done)

```bash
cd global_radio
bash tools/setup_gcp_backend.sh
# Project ID: globalir
# Firestore region: us-central1 (or your preference)
```
This adds Firebase to the project, creates the Firestore database, and
publishes `firestore.rules`. If billing is enabled when prompted, it will
also offer to deploy the `verifyPurchase` Cloud Function (payment
verification) — say yes, or re-run later once billing is confirmed.

## 2. Real audio + catalog → Firebase Storage + Firestore

Regenerate content if it's gone stale (safe to skip if `cdn_dist/` from
2026-07-08 is still good — check `cdn_dist/catalog.json`'s `version` field):

```bash
python -m venv tools/.venv && source tools/.venv/Scripts/activate  # Windows: tools/.venv/Scripts/python.exe
pip install edge-tts requests skyfield
export PYTHONIOENCODING=utf-8   # Windows only — avoids a UnicodeEncodeError on the ✓ character
python tools/build_catalog.py
```

Deploy it (creates the Storage bucket, makes it public, uploads audio,
writes the Firestore `catalog_items` collection):

```bash
bash tools/deploy_content.sh globalir
```

If the bucket doesn't exist yet, create it first (this is the step that
needs billing):

```bash
TOKEN=$(gcloud auth print-access-token)
curl -X POST "https://storage.googleapis.com/storage/v1/b?project=globalir" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"globalir.firebasestorage.app","location":"US-CENTRAL1","iamConfiguration":{"uniformBucketLevelAccess":{"enabled":true}}}'
```

## 3. Point the app at the real Firebase-hosted content

Update `.github/workflows/android-release.yml` and `.github/workflows/ios-build.yml`'s
`DART_DEFINES` block:

```diff
- --dart-define=DEMO_AUDIO=true
+ --dart-define=DEMO_AUDIO=false
+ --dart-define=CDN_BASE=https://storage.googleapis.com/globalir.firebasestorage.app/audio
+ --dart-define=USE_FIRESTORE_CATALOG=true
```

**Before flipping `DEMO_AUDIO=false` in CI, verify manually that this actually
works** — a repeat of the `cdn.globalradio.app`-doesn't-resolve mistake from
2026-07-08 would ship broken playback again:

```bash
curl -I "https://storage.googleapis.com/globalir.firebasestorage.app/audio/hindi/male_story/moral-thirsty-crow-hi.mp3"
# expect: HTTP/2 200
```

Then push a new tag (see README.md's "Releases (CI/CD)" section) and confirm
audio actually plays on a real device before considering this done.

## 4. Decommission the interim GitHub CDN

Once step 3 is verified working, `prince11jose/globalradio-cdn-content` can
be archived or deleted — it was only ever meant to be temporary.

## 5. Payment verification (separate from content — see CHANGELOG.md)

`functions/verifyPurchase` and its service account are provisioned by
`tools/setup_gcp_backend.sh` in step 1 above, gated on billing being enabled.
Two things still need a human with the right accounts, no way around it:
- **Play Console**: Setup → API access → link `globalir`, grant the
  `play-billing-verifier` service account "View financial data" + "Manage
  orders and subscriptions".
- **Apple**: App Store Connect → your app → In-App Purchases → App-Specific
  Shared Secret → feed it to `tools/setup_gcp_backend.sh` when prompted (or
  `gcloud secrets create apple-shared-secret` manually).

## 6. iOS signed builds (separate from all of the above)

Needs `IOS_DIST_CERTIFICATE_BASE64`, `IOS_DIST_CERTIFICATE_PASSWORD`,
`IOS_PROVISIONING_PROFILE_BASE64`, `IOS_KEYCHAIN_PASSWORD` as repo secrets —
see the comment block above the `build-signed` job in
`.github/workflows/ios-build.yml`. Requires interactive access to the Apple
Developer Portal for Team `4H23B2XQN4` — there is no API/CLI path around
this, it's Apple's security model.
