# Changelog

All notable changes to Global Radio are documented in this file.

## 2026-07-08

### Added
- **Server-side purchase verification.** New `functions/verifyPurchase` Cloud Function checks Google Play / App Store purchases against the store before granting premium — previously the client granted itself premium locally the instant the purchase sheet opened, with no server check at all.
- **Firestore security rules** (`firestore.rules`): `isPremium` and related entitlement fields on `users/{uid}` can now only be written by the verification Cloud Function; `requests` and `referrals` collections got their first rules (previously unrestricted).
- **`tools/setup_gcp_backend.sh`**: one-command, idempotent setup for a Firebase/GCP project — adds Firebase, creates the Firestore database (free tier, no billing account needed), publishes `firestore.rules`, and (once billing is enabled) deploys `verifyPurchase` and provisions its service account and Apple shared secret. Chained after `tools/setup_firebase.sh` so handing this project to someone else is a two-script setup.
- Real Android Auto / CarPlay media browsing wired to the actual catalog and offline content (`media_browser_service.dart`), replacing the placeholder hierarchy.
- Engagement features, home-screen widgets, ads improvements, additional l10n, CI workflows, and the marketing landing site (merged from a parallel work stream — see `docs/engagement-strategy.md` and `docs/ads-placement-strategy.md`).
- **CI/CD release pipelines**, both building on GitHub-hosted runners (no local build required):
  - `.github/workflows/ios-build.yml` — every push compiles the iOS target unsigned as a fast correctness check (`macos-15`, no Apple credentials needed); a version tag or manual dispatch additionally produces a signed `.ipa` (and optional TestFlight upload) once the required Apple signing secrets are configured.
  - `.github/workflows/android-release.yml` — a version tag or manual dispatch produces a signed release APK and publishes it as a GitHub Release asset.
  - Both apply the full set of production `--dart-define` flags and fail fast with an explicit message listing exactly which secrets are missing rather than a deep, confusing build error.
- **Real narrated audio is live**, replacing the demo clips: generated 1340 real neural-TTS files (10 languages, every library story) with `tools/build_catalog.py`, hosted on a free interim CDN at `https://raw.githubusercontent.com/prince11jose/globalradio-cdn-content` until Firebase Storage billing is sorted (see `tools/FUTURE_FIREBASE_SETUP.md`). Verified end-to-end with `test/streaming/cdn_streaming_path_test.dart` (catalog fetch + ranged HTTP GET + MP3 validation across all 10 languages) before enabling it in CI — both release workflows now build with `DEMO_AUDIO=false` pointing at this CDN.
- **Firestore-backed catalog option**: `CatalogRepository` can now source the catalog from a Firestore `catalog_items` collection instead of a static `catalog.json` (`USE_FIRESTORE_CATALOG` flag), with `tools/write_catalog_to_firestore.js` to populate it. Not enabled yet (waiting on the real Firebase project's Storage billing — see `tools/FUTURE_FIREBASE_SETUP.md`); the interim CDN above uses the existing static-JSON path.
- `tools/deploy_content.sh`: one-command deploy of the content pipeline's output to Firebase Storage (public CDN bucket) + Firestore, for when billing is enabled on the real project.

### Changed
- `payment_service.dart`: `purchaseInApp()` now only starts the store flow and throws on failure instead of returning a misleading bool; entitlement arrives asynchronously via server verification, exposed through `premiumUpdates` and the Firestore-backed `premiumSyncProvider`.
- `user_db_service.dart` adds `watchPremiumStatus()`, a live stream that is now the single source of truth for premium status app-wide (`ProfileController.applyRemoteEntitlement`), replacing the old client-writable `setPremium()`.
- The app now targets Firebase project `globalradio-1f547` (Android + iOS both configured) rather than the `globalir` project used earlier in the day — `globalir` was a placeholder used while these fixes were built and verified; `globalradio-1f547` is the real one going forward. `.firebaserc`, `google-services.json`, and `firebase_options.dart` all point at it now.

### Fixed
- **Google Sign-In hanging indefinitely.** Root cause: the Firebase project's Firestore database had never been created, so every post-login profile fetch retried forever against a `NOT_FOUND` database. Same root cause blocked voting and referrals. Fixed on the (now superseded) `globalir` project as a proof of the fix — **still needs to be applied to `globalradio-1f547`** by running `tools/setup_gcp_backend.sh` with an account that has access to it (see Known Issues).
- Removed the dead `DevAuthService` mock now that `FirebaseAuthService` is the only auth backend in use.
- `rate_limiter.dart`: certificate pinning now does real SHA-256 fingerprint comparison instead of unconditionally denying every certificate.
- `share_widgets.dart`: `AsyncValue.valueOrNull` doesn't exist in the `riverpod` 3.x this project now pins — replaced with `.value`, which is nullable-safe in 3.x (`valueOrNull` was the 2.x name for the same thing).
- **Android release build was completely non-functional, three separate bugs deep:** the release workflow lived at `global_radio/.github/workflows/release.yml`, a path GitHub Actions never reads (workflows only run from a repo's *root* `.github/workflows/`) — moved to `.github/workflows/android-release.yml`. It also had no `working-directory`, so every step resolved paths against the repo root instead of `global_radio/`. And even building locally, `flutter build apk --release` failed outright with `Dependency ':flutter_local_notifications' requires core library desugaring` — added `isCoreLibraryDesugaringEnabled = true` + the `desugar_jdk_libs` dependency to `android/app/build.gradle.kts` (only surfaces in release builds; debug builds don't run this check, which is why it went unnoticed). Verified via both a local build and CI end to end: [v1.0.1](https://github.com/VivekcMW/GlobalR/releases/tag/v1.0.1).
- GitHub Actions rejects the `secrets` context used directly inside a step `if:` condition ("Unrecognized named-value: 'secrets'") — the TestFlight-upload check in `ios-build.yml` now routes through a step output instead.
- `connectivity_plus` 7.2.0's iOS Swift code needs a newer Xcode than the `macos-14` runner ships (`NWPath.isUltraConstrained` doesn't exist there) — switched `ios-build.yml` to `macos-15`.

### Security
- Closed a client-side premium spoofing bug: `settings_screen.dart` was granting premium the instant `buyNonConsumable()` returned (which only means the purchase dialog opened, not that payment completed), with no server check and no Firestore rule stopping a client from writing `isPremium: true` directly.

### Known issues / follow-ups
- **Backend not yet provisioned on the real project.** `tools/setup_gcp_backend.sh` needs to be run against `globalradio-1f547` by someone with GCP access to it (the account used today, `prince11jose@gmail.com`, does not have access). Until then, Google Sign-In on this project will hang the same way it did before today's fix, and `verifyPurchase` isn't deployed.
- **Referral "gift premium" is now local-only.** `referral_screen.dart` used to flip `isPremium` straight to Firestore; since that field is now server-write-only, redeeming a referral gift updates the local profile only (via `applyRemoteEntitlement`) and won't sync across devices or survive an unrelated profile save overwriting it from the Firestore listener. Needs a small server-side grant path (e.g. a callable function) if referral-granted premium should persist for real — out of scope for today's purchase-verification fix.
- Voting (`voting_service.dart`) was intentionally reverted to local-only storage (no Firestore) in the parallel work stream merged today; the `requests` collection rule in `firestore.rules` is currently unused until/unless that's revisited.
- **No signed iOS builds yet.** `ios-build.yml`'s `build-signed` job needs `IOS_DIST_CERTIFICATE_BASE64`, `IOS_DIST_CERTIFICATE_PASSWORD`, `IOS_PROVISIONING_PROFILE_BASE64`, and `IOS_KEYCHAIN_PASSWORD` as repo secrets. These can only come from whoever holds the Apple Developer account for Team `4H23B2XQN4` (cert/profile generation requires interactive 2FA-protected access to the Apple Developer Portal — there's no API or CLI path around this). See the comment block above `build-signed` in `.github/workflows/ios-build.yml` for exactly how to generate and add them.
- **`DEMO_AUDIO=false` is back, this time verified against real, working content.** Earlier today it was flipped to `false` pointing at `cdn.globalradio.app`, a domain that doesn't resolve at all ([v1.0.1](https://github.com/VivekcMW/GlobalR/releases/tag/v1.0.1) and v1.0.2 both shipped broken because of it — every item failed to load and playback silently skipped the whole queue forever). This time `CDN_BASE`/`CATALOG_URL` point at the real interim GitHub CDN described above, and `test/streaming/cdn_streaming_path_test.dart` was run against it and passed (catalog fetch + ranged GET + MP3 validation, all 10 languages) before the CI workflows were updated — not just assumed. Migrate to Firebase Storage per `tools/FUTURE_FIREBASE_SETUP.md` once billing/access exist on the real project; re-run that test against the new `CDN_BASE` before flipping anything.
- **Cloud Storage has no free tier for bucket creation** (unlike Firestore) — confirmed directly via `gcloud beta billing projects describe` and a 403 from the Storage API citing "billing account ... disabled". This, plus no IAM access to `globalradio-1f547`, is why the interim GitHub CDN exists instead of Firebase Storage. See `tools/FUTURE_FIREBASE_SETUP.md` for the full migration checklist once both are resolved.
